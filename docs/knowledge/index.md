# gunkata knowledge base

This bundle holds what must still be true in a fresh clone, to a reader who was not in the
session that learned it: findings about the tools and platforms gunkata depends on, and
references to outside material the project relies on. Design law lives in `/docs/spec.md`
and `/AGENTS.md`, never here. One concept per file, full frontmatter, sources on every
claim.

It refuses three things. **State** - run counts, in-flight work, versions of things that
change with the next commit - belongs to its authoritative source, not here; a number lives
in a concept only when the number is the finding. **Secrets** of any kind, because git
history is permanent. **Standing orders**, which belong in `/AGENTS.md`: when a decision
produces both a law and a rationale, `AGENTS.md` gets the one-line law and the rationale
lives here.

Conventions: `findings/` holds `Finding`, `references/` holds `Reference`, and the
generator rejects anything else. Deprecate, never delete. The listing
below is generated by `scripts/kb_index.py` - edit concepts and regenerate; pre-commit
enforces `--check`. There is no update log; git history is the log.

# Findings

* [A gate must run inside the pinned dev shell](findings/a-gate-must-run-inside-the-pinned-dev-shell.md) - A hook inherits the invoking shell, so an environment cached before a flake change fails the gate with a bare exit 127; the pre-push hook therefore wraps itself in nix develop.
* [acpx loads Claude with project and local settings only](findings/acpx-claude-skips-user-settings-by-default.md) - acpx launches Claude Code with --setting-sources=project,local, so skills and settings placed in the executor HOME's .claude (user scope) are ignored unless ACPX_CLAUDE_INCLUDE_USER_SETTINGS=1 is set.
* [acpx --format json emits the raw ACP JSON-RPC stream](findings/acpx-json-format-is-the-raw-acp-stream.md) - With --format json acpx writes the ACP JSON-RPC traffic to stdout one object per line - session/update notifications for tool calls, usage and thought chunks, the client requests, and their responses, with stopReason and token usage on the prompt response - and --json-strict keeps non-JSON off it.
* [Claude MCP OAuth tokens are keyed by server name plus a hash of its exact config](findings/claude-mcp-oauth-tokens-keyed-by-server-identity.md) - Claude Code stores MCP OAuth tokens in .credentials.json under "<name>|" + the first 16 hex of sha256 over {type,url,headers}, so a server passed on acpx stdin reuses a stored login only when name, exact URL and empty headers match - and linking the file hands the agent every stored token.
* [A Claude subscription login loads the account's claude.ai connectors into a bare executor](findings/claude-subscription-login-loads-claudeai-connectors.md) - A Claude executor authenticated with the subscription OAuth login auto-loads every claude.ai connector on the account (Gmail, Slack, Drive, Calendar, glim...); ENABLE_CLAUDEAI_MCP_SERVERS=false stops it, and an allowedMcpServers list keyed by serverUrl is the selective alternative.
* [A Claude executor inherits CLAUDE.md files and skills from its cwd's ancestors](findings/claude-walks-ancestor-dirs-for-instructions-and-skills.md) - Claude Code walks the ancestors of its cwd for CLAUDE.md and .claude/skills; the skill walk stops at $HOME or a git root, so a work dir nested inside the executor's own HOME is bounded, and CLAUDE_CODE_DISABLE_CLAUDE_MDS=1 stops the unbounded CLAUDE.md walk.
