# gunkata workflow spec (v1)

Normative. What a workflow file may say and what the engine guarantees for it.
A run does what the file says - nothing is built in: no roles, no prompts, no
implicit steps.

## File

```yaml
name: <workflow>

params:                        # everything invocation-specific; nothing else enters a run
  <key>: {}                    #   required: gunkata run w.yaml -p key=value
  <key>: {default: <value>}    #   optional

agents:                        # a profile fully describes one executor shape
  <profile>:
    harness: <id>              # required
    model: <id>                # required
    timeout_seconds: <int>     # optional
    options: {}                # optional harness-specific settings

workflow:                      # map of jobs = the DAG
  <job>:
    needs: [<job>, ...]        # DAG edges; absent = root
    pre-steps:                 # deterministic setup: engine-run argv, no shell, no model
      - [<argv>...]
    agent: <profile>           # required iff prompt is present
    prompt: |                  # the judgment; the only place a model acts
      ...
    outputs: [<name>, ...]     # files owed, land in artifacts/<job>/
    post-steps:                # the done-bit; all exit 0 = verified
      - [<argv>...]
```

Four top-level keys. Seven job keys. Unknown fields are rejected.

## Semantics

A job is setup, judgment, evidence:

1. `pre-steps` run first, in order. Any non-zero exit fails the job. Never
   retried: their failure is deterministic.
2. `prompt` runs the profile's executor once, in a bare engine-owned HOME,
   cwd = the job's own working directory. Nothing is inherited except
   subscription auth.
3. `outputs` are the files the job owes. Each gets an implicit non-empty
   presence check. `post-steps` add the semantic checks. All checks passing
   is the only thing that makes a job done; dependents release on nothing
   else. A job must declare at least one output or post-step.

A job without `prompt` is a deterministic job: no agent, no model, just
steps and evidence.

Failure parks the job, and nothing that needs it ever runs. There is no
retry in v1; retry arrives only with transcript-based failure
classification (lock 4).

## Placeholders

Three kinds, expanded in one pass, to absolute paths only:

- `{{param:key}}` - the bound value of a param
- `{{output:name}}` - the job's own output, under `artifacts/<job>/`
- `{{artifact:job/name}}` - an upstream job's output

No content splicing, no expressions, no second pass. Referencing an
artifact does not create an edge; only `needs:` does.

## Run

`gunkata run w.yaml -p key=value ...`

1. Bind: every required param bound exactly once, no undeclared bindings.
   A param whose value is an existing file is snapshotted into the run dir,
   and the placeholder expands to the snapshot - the run dir is a complete,
   self-contained evidence record.
2. Validate: unresolved profile/need/param/artifact references and cycles
   are rejected before anything runs.
3. Execute: roots start; each verified job releases its dependents.
4. Every run is fully isolated: own directories, ports, HOMEs; teardown
   kills the whole process tree.

## Deliberately absent

No templating, includes, extends, or expression language - repetitive
workflows are generated by a real program; the file stays dumb. No string
outputs between jobs - files only. No shell in any declared command. No
secrets in the file - executor auth inherits from the environment. No
per-job overrides of profile fields - a different shape is a different
profile. Matrix, workspace provisioning, retry, per-profile
skills/mcps/env, allow_failure, and concurrency knobs stay out until a
real workflow demands them.
